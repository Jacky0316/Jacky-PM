## 一、需求背景

星马特平台商家端已具备店铺资质上传与审核功能，但用户端（线上商城商品页、商圈线下门店页）的店铺展示区域**尚未透出资质信息**。用户无法感知店铺是否具备经营资质，影响购买信任度。

本次需求仅新增星码特线上商城店铺和线下商圈店铺主页资质标识展示，在两个店铺展示位置增加资质标识图标，并支持点击查看完整资质内容。

---

## 二、涉及页面与位置

| 页面 | 展示位置 | 现状 |
|------|--------|------|
| 线上商城 - 商品详情页 | 底部店铺信息卡片（店铺名称行） | 仅有店铺名、关注数、查看店铺按钮 |
| 商圈 - 线下门店详情页 | 门店基本信息区（店铺名称行） | 仅有店铺名、关注数等基础信息 |

---

## 三、功能详述

### 3.1 资质标识展示规则

- **有资质（至少一项审核通过）**：在店铺名称右侧展示资质标识，样式为小图标 + 「资质认证」文字；
- **无资质或全部未通过**：不展示标识，不占位，保持原有布局不变。

**布局示意（线上商城店铺主页）：**

```
┌────────────────────────────────────────────────┐
│  [店铺Logo]  天津市金诺康科技有限公司   
│             🛡️资质认证    查看资质 >     收藏
               店铺简介介绍               0人已关注
└────────────────────────────────────────────────┘
```

**布局示意（商圈门店主页）：**

```
┌────────────────────────────────────────────────┐
│  贵州剪藏城郊花样园超市                                       
│  🛡️资质认证   查看资质   收藏
   店铺地址
   联系电话  营业时间                          
└────────────────────────────────────────────────┘
```

---

### 3.2 点击资质标识 - 查看资质弹窗

用户点击资质标识图标或文字后，弹出居中弹窗（Modal），展示该店铺的营业执照图片（打码处理版本）。

**弹窗内容结构：**

```
┌────────────────────────────────┐
│        店铺资质               ✕ │
│ ─────────────────────────────  │
│                                │
│   [营业执照图片（关键信息打码）]   │
│                                │
│   以上资质已经平台审核            │
│   更新时间：2026-03-15          │
└────────────────────────────────┘
```

**交互细节：**

- 点击右上角「✕」或弹窗蒙层关闭弹窗；
- 展示内容：仅展示营业执照，图片为商家上传后经平台打码处理的版本（遮盖注册号、法人姓名等敏感字段）；
- 图片支持双指缩放查看；

---

## 四、异常处理

| 场景 | 处理方式 |
|------|--------|
| 营业执照图片加载失败 | 展示占位图，提示「图片加载失败」 |
| 弹窗数据请求超时 | 展示错误提示并提供重试按钮 |
| 所有资质均已过期 | 不展示标识（等同于无资质状态） |

---

## 五、接口依赖

前端需新增一个接口（或复用已有接口），入参为店铺 ID，返回该店铺所有审核通过的资质列表：

| 字段 | 类型 | 说明 |
|------|------|------|
| qualification_type | String | 资质类型名称 |
| images | Array\<String\> | 证件图片 URL 列表 |
| expire_date | Date / null | 有效期，无则为 null |
| reviewed_at | DateTime | 平台审核通过时间 |

> 需与后端确认：现有资质数据接口是否已有公开查询能力，或需新增面向 C 端的查询接口。

## 六、待确认事项

1. **资质标识文案**：「资质认证」「已认证」「证照齐全」，哪个更合适？由设计/业务确认；
2. **有效期过期处理**：证件到期后该条资质是否自动从 C 端隐藏（建议是），需后端确认过期判断逻辑是否已有；
3. **接口权限**：C 端查询资质是否需要用户登录，或游客也可查看？建议游客可查，保持信任透明。
