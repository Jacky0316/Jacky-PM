## 一、需求背景分析

### 1.1 当前业务现状

星码特平台定位为一个S2B2C综合电商平台，当前已具备两大核心业务板块：

| 业务板块 | 模式 | 参与角色 | 核心流程 |
| --- | --- | --- | --- |
| 供应商官方店 | B2C | 供应商、C端用户、平台 | 供应商入驻→发布商品→用户线上下单→平台订单履约→用户收货 |
| 门店商圈服务 | O2O | 线下门店、C端用户、平台 | 门店入驻商圈→开通支付→提供线下服务→用户到店消费 |

现有终端矩阵：

*   **平台端PC**：平台运营管理后台
*   **供应端PC**：供应商日常经营管理后台
*   **门店H5**：线下门店员工操作端
*   **商家H5**：商圈商家管理端
*   **用户H5**：C端用户购物端

### 1.2 当前业务痛点

1.  **门店进货渠道缺失**：现有线下门店仅能提供支付和线下服务，缺乏稳定、透明的批发进货渠道。门店需要自行寻找供应商，采购成本高、效率低、品控难保障。
2.  **供应商销售渠道单一**：供应商仅能通过官方店进行C端零售，无法触达平台已沉淀的大量线下门店资源，批发业务增量未释放。
3.  **平台业务闭环不完整**：S2B2C模式中"S→B"链路缺失，平台仅完成了S→C和B→C的局部连接，未能形成供应商→门店→用户的完整价值链条。
4.  **门店资产利用率低**：门店入驻后除提供服务外，无法通过商品零售产生额外收益，门店经营积极性和平台粘性不足。

### 1.3 不做该需求的影响

*   **门店侧**：门店因缺乏进货渠道而流失至竞品平台，现有商圈生态萎缩。
*   **供应商侧**：供应商仅依赖零售，无法发挥批发规模效应，平台对供应商的吸引力下降。
*   **平台侧**：GMV增长天花板明显，S2B2C战略定位无法落地，在供应链服务平台竞争中处于劣势。

## 二、需求目标确认

### 2.1 核心目标

搭建星码特平台B2B批发业务模式，实现供应商与门店之间的高效批发交易闭环，并赋能门店向C端用户零售商品。

### 2.2 具体目标

| 目标编号 | 目标描述 | 可衡量标准 |
| --- | --- | --- |
| G1 | 打通供应商→门店的批发进货渠道 | 供应商开通批发功能后，可主动绑定合作门店并接收批发订单 |
| G2 | 实现批发商品定价与交易 | 支持按门店等级分级折扣定价，满足最低起订量后下单 |
| G3 | 完成批发订单履约闭环 | 批发订单具备独立的履约流程，支持快递配送至门店 |
| G4 | 赋能门店C端零售 | 门店批发进货后，可将商品上架至门店主页售卖给C端用户，支持到店自提 |
| G5 | 建立批发业务结算体系 | 支持T+1结算、平台佣金扣除、供应商给门店开票 |

### 2.3 目标用户与角色

| 角色 | 定义 | 核心诉求 |
| --- | --- | --- |
| 平台运营 | 星码特平台运营人员 | 管理批发权限、监控交易数据、处理异常订单、保障结算准确 |
| 供应商 | 入驻平台的品牌商/批发商 | 拓展门店批发客户、管理批发商品与价格、高效处理批发订单、按时回款 |
| 门店 | 入驻商圈的线下门店 | 便捷采购商品、获得价格优势、在门店主页零售增收 |
| C端用户 | 普通消费者 | 在门店主页浏览商品、下单购买、到店自提 |

## 三、业务流程分析

### 3.1 当前流程（现状）

```

    subgraph 供应商官方店业务流程
        A1[供应商申请入驻] --> A2[平台审核通过]
        A2 --> A3[供应商发布商品]
        A3 --> A4[C端用户在用户H5浏览]
        A4 --> A5[用户下单支付]
        A5 --> A6[平台订单履约系统处理]
        A6 --> A7[快递配送到用户]
        A7 --> A8[用户确认收货]
        A8 --> A9[T+N结算给供应商]
    end

    subgraph 门店商圈业务流程
        B1[门店申请入驻商圈] --> B2[平台审核通过]
        B2 --> B3[门店开通支付功能]
        B3 --> B4[门店发布线下服务]
        B4 --> B5[C端用户在用户H5浏览服务]
        B5 --> B6[用户购买服务/预约]
        B6 --> B7[用户到店消费]
        B7 --> B8[门店核销订单]
    end

    style A1 fill:#f9f,stroke:#333
    style B1 fill:#f9f,stroke:#333
```

**现状流程说明**：

*   供应商与门店之间无直接业务连接，各自独立服务于C端用户。
*   门店无法售卖实体商品，仅能提供线下服务类订单。
*   平台作为撮合方，分别管理零售订单和服务订单，未涉及批发交易。

### 3.2 目标流程（改善后）

```
graph TD
    subgraph 供应商开通批发流程
        S1[供应商入驻平台] --> S2[供应商申请开通批发权限]
        S2 --> S3[平台运营审核]
        S3 -->|审核通过| S4[供应商获得批发权限]
        S3 -->|审核拒绝| S5[告知原因，可再次申请]
        S4 --> S6[供应商设置批发商品]
        S6 --> S7[设置批发价/起订量/佣金比例]
        S7 --> S8[供应商手动搜索并绑定合作门店]
        S8 --> S9[门店收到合作邀请并确认]
    end

    subgraph 门店批发进货流程
        M1[门店在H5进入批发进货入口] --> M2[浏览合作供应商的批发商品]
        M2 --> M3[选择SKU和数量]
        M3 --> M4{数量>=最低起订量}
        M4 -->|否| M3
        M4 -->|是| M5[加入购物车]
        M5 --> M6[提交批发订单]
        M6 --> M7[选择支付方式]
        M7 -->|平台余额/在线支付| M8[完成支付]
        M7 -->|货到付款| M9[订单进入待发货]
        M8 --> M10[订单进入待发货]
        M10 --> M11[供应商接单并发货]
        M9 --> M11
        M11 --> M12[快递配送至门店]
        M12 --> M13[门店确认收货]
    end

    subgraph 门店零售给C端用户流程
        R1[门店将进货商品上架至门店主页] --> R2[C端用户访问门店主页]
        R2 --> R3[浏览商品并下单]
        R3 --> R4[用户支付]
        R4 --> R5[用户到店自提]
        R5 --> R6[门店核销自提码]
        R6 --> R7[交易完成]
    end

    subgraph 结算与开票流程
        C1[门店确认收货] --> C2[平台生成结算单]
        C2 --> C3[扣除平台佣金]
        C3 --> C4[T+1结算给供应商]
        C4 --> C5[供应商给门店开具发票]
    end

    S9 --> M1
    M13 --> C1
```

**目标流程说明**：

*   供应商与门店建立明确的合作关系，由供应商主动绑定。
*   批发交易具备独立的订单履约流程，与零售订单解耦。
*   门店收货后可开启C端零售，形成"供应商→门店→用户"的完整链路。
*   结算与开票围绕批发订单闭环运行。

### 3.3 核心子流程详述

#### 3.3.1 批发价格计算流程

```
graph LR
    A[门店发起下单] --> B[系统识别门店在供应商处的等级]
    B --> C[获取供应商为该等级设置的折扣]
    C --> D[查询SKU是否有特殊批发价]
    D -->|有| E[使用特殊批发价]
    D -->|无| F[使用商城零售价*等级折扣]
    E --> G[计算最终批发价]
    F --> G
    G --> H{数量>=最低起订量}
    H -->|是| I[允许下单]
    H -->|否| J[提示未满足起订量]
```

#### 3.3.2 批发订单履约状态流转

```
graph LR
    A[待付款] -->|支付成功| B[待发货]
    A -->|货到付款| B
    B -->|供应商发货| C[待收货]
    C -->|门店确认收货| D[已完成]
    C -->|物流异常| E[异常处理]
    E -->|问题解决| D
    A -->|超时未支付| F[已取消]
```
