## 二、需求背景与目标

### 2.1 需求背景

**业务现状**：
- 星马特平台已具备B2C线上商城和线下门店O2O业务模式
- 线下门店与供应商之间缺乏规范的批发进货流程和数字化工具支持该业务
- 供应商无法对不同门店进行差异化定价，商品批发价格管理不灵活
- 用户线上购物与线下门店之间缺乏联动，无法享受到店自提服务
- 线上标价与批发价脱节，商品信息同步效率低

**问题分析**：
- 门店进货缺乏系统化管理，商品信息、库存、价格难以保持一致
- 供应商无法按门店等级设置差异化折扣，价格体系不完整
- 用户在线上下单仅支持配送，无到店自提选项，门店流量未得到有效引导
- 平台交易链路不完整，供应链管理和渠道合作缺乏工具支持

### 2.2 迭代目标

| 目标 | 描述 | 衡量指标 |
|------|------|--------|
| 建立批发进货体系 | 规范线下门店向供应商的进货流程，确保商品信息、库存、价格的一致性管理 | 门店通过平台完成进货的订单占比 ≥ 80% |
| 实现灵活价格管理 | 供应商可按门店等级、商品维度进行差异化定价，支持多层级折扣和批发数量限制 | 供应商批发价配置完成率 ≥ 90% |
| 打通线上线下链路 | 用户线上下单可选择线下门店提货，提升购物体验和门店流量 | 自提订单占比提升至 10%+，门店核销率 ≥ 95% |

### 2.3 成功指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 进货订单完结率 | ≥ 95% | 门店完成收货确认的进货订单比例 |
| 商品自动同步率 | 100% | 进货完结后商品自动同步至门店展示页的比例 |
| 自提订单核销率 | ≥ 95% | 用户到店完成核销的自提订单比例 |
| 批发价计算准确率 | 100% | 系统按公式计算的批发价与预期一致的比例 |

### 3.2 核心业务场景

#### 场景1：供应商设置门店等级和商品批发价

**场景描述**：
- **背景**：供应商有多家合作门店，不同等级门店享受不同商品批发优惠
- **用户目标**：供应商为不同等级的门店设置差异化折扣，精细化管理价格体系
- **预期结果**：门店进货时看到的批发价与其等级折扣一致，价格计算准确

**具体步骤**：
1. 供应商通过门店ID绑定合作门店，获取门店的信息同时，再设置门店等级
2. 供应商配置全局商品批发价折扣，门店批发门槛等或对单个商品可以设置自定义折扣
3. 门店进货时，系统自动按公式计算并展示对应商品批发价

**涉及角色**：供应商 / 线下门店

#### 场景2：门店向供应商发起批发进货

**场景描述**：
- **背景**：某门店库存不足，需向平台上的合作供应商补货
- **用户目标**：门店完成选品、下单、收货全流程，收货后系统自动同步商品至门店线上展示区
- **预期结果**：进货订单完结，商品自动上架至门店线上页面，平台自动结算

**具体步骤**：
1. 供应商在后台通过店铺ID添加门店，并为其设置等级和批发价
2. 门店在进货管理中查看可合作供应商、进货商品及商品对应批发价
3. 门店选择批发商品，创建进货订单（选择商品、确认数量和批发价）
4. 供应商确认订单并安排出库发货
5. 门店收货验货，确认收货后订单完结
6. 系统自动将商品同步至门店线上展示页，平台完成结算

**涉及角色**：供应商 / 线下门店 / 系统 


#### 场景3：用户线上下单选择到店自提商品

**场景描述**：
- **背景**：用户在线上商城看中商品，希望到就近门店取货
- **用户目标**：完成线上支付，选择附近门店自提，减少等待配送的时间
- **预期结果**：用户到店后凭核销码顺利提货，门店完成核销，货款直接结算至门店账户

**具体步骤**：
1. 用户在线上商城对一个商品下单时，在详情页看到"到店自提"选项
2. 用户选择到店自提模式，选择一个与供应商已合作且距离最近的门店
3. 用户完成线上支付，系统生成自提订单及核销码
4. 用户到店出示核销码，门店核销提货
5. 订单完结，支付金额结算至门店账户

**涉及角色**：终端用户 / 线下门店 / 系统

## 四、核心业务流程

### 4.1 当前业务流程

**流程说明**：门店与供应商通过线下沟通进货，无系统化管理；商品信息需人工同步至线上；线上订单仅支持配送。

**现有问题**：
- 进货流程完全线下，缺乏留痕和追溯
- 商品信息需手动维护，同步效率低且易出错
- 线上订单不支持自提，门店流量未得到有效利用
- 批发价格分散管理，无差异化折扣工具

### 4.2 目标业务流程

**批发进货流程**：
```
门店申请合作 → 供应商手动设置门店等级和商品批发价
      ↓
门店查看商品及批发价 → 创建进货订单 → 供应商收到订单出库发货
      ↓
物流发货 → 门店收货验货 → 确认收货
      ↓
系统自动同步商品至门店线上展示 → 平台自动结算
```

**门店等级及商品批发价设置流程**：
```
供应商后台
  ├─ 添加门店（店铺ID）→ 同步门店基础信息 → 设置门店等级
  ├─ 全局批发价设置（基础批发价 + 按等级折扣）
  └─ 商品级自定义折扣
         ↓
  批发价 = 优惠后价格 × 门店等级折扣
```

**用户线上下单选择到店自提流程**：
```
用户线上选购 → 结算页选择"到店自提" → 选择门店 → 完成线上支付
      ↓
订单生成（标记自提）→ 门店接收自提订单
      ↓
用户到店出示核销码 → 门店核销 → 提货完结 → 货款结算至门店账户
```

**改进点**：
- 进货全程系统化，支持订单追踪与平台自动结算
- 商品进货完结后自动同步上架，无需人工干预
- 线上商城支持到店自提，打通线上线下购物链路

## 五、功能范围与清单

### 5.1 功能范围界定

**本次迭代包含的功能**：
- 需求1：线下门店向供应商批发进货全流程
- 需求2：供应商设置门店等级与商品批发价功能
- 需求3：线上商城订单支持"到店自提"模式
- 需求5：门店商品展示与商品订单管理（门店端支持展示从供应商采购的商品，接收用户商品订单）

**暂不包含的功能（后续迭代）**：
- 需求4：平台商家合伙人功能 - 属于第二阶段，优先保证核心供应链流程
- 需求5：线下门店区域代理功能 - 属于第二阶段，依赖门店等级体系稳定
- 门店直接发货履约方式 - 当前仅支持自提，后续按需扩展
- 批量设置商品价格体系（P1）- 优先支持单品设置，批量工具后续补充

**依赖关系**：
- 需求3（自提）依赖需求1中供应商与门店的合作关系已建立
- 需求2的批发价计算依赖需求1中门店等级体系的完善

#### 6.1.4 交互说明

| 交互项 | 触发条件 | 反馈 | 说明 |
|--------|--------|------|------|
| 打开添加门店弹窗 | 供应商点击"[+ 添加门店]"按钮 | 展示弹窗，输入框获焦 | - |
| 输入门店ID | 供应商输入店铺ID | 实时校验，ID有效时自动同步门店信息 | 支持粘贴动作 |
| 自动同步门店信息 | ID校验通过 | 展示门店名称、地址、负责人、联系电话等 | 信息自动填充，不可编辑 |
| 选择门店等级 | 供应商点击等级下拉框 | 展示等级选项（1-5级），供应商选择 | 默认选中1级，可按需调整 |
| 输入备注 | 供应商在备注字段输入文本 | 实时保存，无长度限制（建议≤200字） | 可选项，不影响功能 |
| 确认添加 | 供应商点击"确认添加"按钮 | 门店添加成功，弹窗关闭，列表更新 | 详见业务规则 |
| 删除已添加的门店 | 供应商点击门店操作栏"删除"按钮 | 二次确认弹窗，确认后删除门店及相关配置 | 仅在无进行中订单时可删除 |

**异常处理**：

- **规则1**：**批发价公式**：`最终批发价 = 优惠后价格 × (自定义折扣 OR 全局折扣) × 门店等级折扣`
- **规则2**：零售价由供应商统一设定，所有门店展示同一零售价，门店不可调整
- **规则3**：全局折扣变更仅对变更后新创建的进货订单生效，既有订单的价格以当时快照为准
- **规则4**：等级折扣变更仅对该等级所有新订单生效，不影响既有订单价格
- **规则5**：商品级自定义折扣优先级高于全局折扣，设置后覆盖全局设置
- **规则6**：优惠后价格为可选项，默认等于零售价；若设置则作为批发价计算基础
- **规则7**：供应商在价格设置界面可实时预览各等级的最终批发价
- **规则8**：**批发数量限制**：门店进货时，每个商品的最小批发量 = 商品级最小批发量 OR 全局最小批发量（商品级优先）
- **规则9**：若最小批发量 > 0，门店下单时系统校验数量不得低于限制，否则提示"该商品最小批发量为X件"
- **规则10**：最小批发量设置变更仅对新订单生效，既有订单不受影响

- **可达性**：系统后台自动执行，无用户界面

#### 6.5.2 原型链接

无（系统后台功能）

#### 6.5.3 功能描述

商品自动同步功能是指当门店完成进货订单收货确认后，系统自动将该订单中的商品同步至该门店的线上展示页面，包括商品信息、库存和价格。

#### 6.5.4 同步逻辑

**同步触发条件**：
- 门店在进货订单管理中点击"确认收货"
- 订单状态更新为"已完结"
- 系统自动触发同步任务

**同步内容**：
- 商品基本信息：名称、描述、图片、规格等
- 价格信息：零售价（供应商统一定价）
- 库存信息：以实收数量为准
- 展示状态：自动上架至门店线上页面

**同步规则**：
- **规则1**：同步的商品仅在该门店的线上展示页可见，不影响其他门店
- **规则2**：商品零售价以供应商统一定价为准，门店不可修改
- **规则3**：库存数量以门店实际收货数量为准，支持后续手动调整
- **规则4**：若商品已在门店展示页存在，则更新库存（累加）；若不存在，则新增商品
- **规则5**：同步完成后，商品自动上架状态为"上架"

#### 6.5.5 异常处理

- **场景1**：同步失败时，系统记录失败原因，3分钟后自动重试，最多重试3次
- **场景2**：重试失败后，生成告警通知技术团队处理，同时门店可手动触发同步
- **场景3**：商品信息不完整（如缺少图片），同步时跳过该商品并记录日志

#### 6.6.1 功能入口

- **触发方式**：系统自动触发（门店确认收货后）
- **前置条件**：进货订单完结（门店确认收货）
- **可达性**：系统后台自动执行，无用户界面

#### 6.6.2 原型链接

无（系统后台功能）

#### 6.6.3 功能描述

进货订单自动结算功能是指当门店完成收货确认后，系统自动计算应结算金额，并在约定周期内完成供应商与平台的资金结算。

#### 6.6.4 结算逻辑

**结算触发条件**：
- 门店确认收货，订单状态更新为"已完结"
- 系统自动触发结算任务

**结算计算**：
- 结算金额 = 订单总金额（按价格快照计算）
- 结算周期：T+N个工作日（具体N值待业务确认，建议默认T+1工作日）
- 结算方式：自动转账至供应商账户

**结算规则**：
- **规则1**：结算金额以订单创建时的价格快照为准，防止事后价格调整影响结算
- **规则2**：结算周期从订单完结时间开始计算工作日
- **规则3**：结算失败时，系统自动重试，最多重试3次
- **规则4**：结算完成后，生成结算记录供供应商查询
- **规则5**：平台可根据业务需要设置结算手续费（具体比例待业务确认，当前版本暂不抽佣）

#### 6.6.5 异常处理

- **场景1**：供应商账户信息异常，结算失败，生成告警通知财务团队
- **场景2**：结算金额与订单金额不一致，系统拦截并记录异常
- **场景3**：结算周期内供应商账户变更，需人工确认后重试

- **规则1**：结算无人工干预，完全自动化
- **规则2**：结算准确率100%，金额与订单快照一致

## 十一、术语表

| 术语 | 解释 | 备注 |
|------|------|------|
| 批发价 | 供应商向门店出售商品的价格，= 优惠后价格 × (自定义折扣 OR 全局折扣) × 门店等级折扣 | 区别于零售价 |
| 门店等级 | 供应商为合作门店设置的分级（1-5级），等级越高折扣越优惠 | 等级数量及命名待确认 |
| 核销码 | 用户选择自提后系统生成的唯一取货凭证，一次性有效 | 可为数字码或二维码 |
| 到店自提 | 用户线上支付后，到指定门店凭核销码取货的履约方式 | 当前版本不支持门店发货 |
| 全局批发折扣 | 供应商对所有商品统一设置的默认批发折扣率 | 可被商品级折扣覆盖 |
| 商品级折扣 | 供应商针对特定商品单独设置的批发折扣率，优先级高于全局折扣 | - |
| 价格快照 | 进货订单创建时记录的商品价格信息，防止事后价格调整影响历史订单 | 包含批发价、折扣等信息 |
| 促销比例 | 供应商设置的额外促销激励比例，用于返积分/红包等 | P1功能，本期暂不交付 |
| 合作门店 | 供应商已添加并设置等级的门店，可进行批发交易 | 门店等级决定批发折扣 |
